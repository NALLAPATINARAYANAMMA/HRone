# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It uses the machine-local, potentially naive datetime and assumes the punch-in date is the shift-start date. It also fails to truncate instants before calculating. | Test an overnight punch-in after midnight or a timestamp with fractional seconds. | Convert instants to UTC/IST consistently, derive the attendance day from the shift, and truncate request timestamps to whole seconds. |
| 2 | `compute_work_hours` | Python `round` uses ties-to-even instead of the required decimal half-up rounding. | Test a duration whose hours land exactly halfway between two hundredths. | Use `Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It calculates against the same date even for overnight shifts and counts any positive minutes, not only overtime of at least 30 minutes. | Test a 22:00–06:00 shift that ends the next day, and a punch-out 29 minutes after shift end. | Calculate the correct IST shift-end instant and apply the 30-minute minimum. |
| 4 | `/health` | It always returns success without checking MongoDB. | Stop MongoDB and request `/health`; the starter still reports `ok`. | Ping MongoDB and return 503 when the ping fails. |
| 5 | `EmployeeIn` | It does not enforce the contract’s employee code, email, length, date, shift-time, or distinct-shift rules. | Submit malformed codes, dates, times, or identical shift times. | Add Pydantic field and model validation. |
| 6 | `create_employee` | A pre-insert duplicate check is not race-safe; `created_at` is naive local time. | Send simultaneous creates for the same `emp_code`, or inspect the stored timestamp. | Enforce uniqueness with a MongoDB unique index, translate duplicate-key errors to 409, and store UTC time. |
| 7 | `list_employees` | Page 1 skips the first page, results are not sorted, and `total` ignores the department filter. | Request page 1 and compare a filtered result’s total with the number of matching employees. | Use `(page - 1) * page_size`, sort by `emp_code`, count the filtered query, and validate pagination bounds. |
| 8 | `punch_in` | Unknown employees cause a server error; timestamp conversion uses local time and treats zero as omitted; status is unchecked. The duplicate pre-check also races. | Punch for an unknown code, send an invalid timestamp/status, or issue concurrent punches. | Return 404 for an unknown employee, validate strict epoch milliseconds/status, convert in UTC, and rely on the unique `(emp_code, date)` index for 409 race handling. |
| 9 | `punch_in` response | It exposes an `id`, although the API identifies records by `emp_code` and `date` and must not expose MongoDB `_id`. | Inspect the response for an `id` field. | Remove internal IDs from every response. |
| 10 | `list_attendance` | It loads and sorts the whole collection in Python, which is unsuitable for 100,000 records; its sort also lacks the `emp_code` tie-breaker. | Measure memory/time on a large collection or compare records with equal dates. | Filter, sort, count, skip, and limit in MongoDB; use the specified compound ordering and indexes. |
| 11 | `list_attendance` | It does not validate calendar dates, reversed ranges, page bounds, or status values, and serializes instants in the wrong shape. | Send an invalid date/range or inspect returned timestamp fields. | Validate query inputs, constrain pagination/status, and serialize BSON dates as epoch milliseconds. |
| 12 | API coverage | Punch-out, regularization, all analytics, and explain routes are absent from the starter. | Request any of those contract paths. | Implement each missing route, with MongoDB aggregation pipelines for analytics and execution-stat explain output. |

**Checked and not a defect:** the sample records’ `date` values are strings and their instants are BSON dates represented in Extended JSON. That distinction is intentional in `DATA_MODEL.md`; the API converts only instants at its boundary.
